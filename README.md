# OpenClaw 云端部署与运维

在一台 **2 核 2G 的云服务器**上，从零完成 AI Agent（OpenClaw）的部署、服务化、安全加固、备份与故障排查，并打通「飞书消息 → AI Agent → 飞书回复」全链路。

> 本文档中所有公网 IP、实例 ID、App ID 等均已脱敏。部署笔记记录的是真实操作过程与真实踩过的坑。

---

## 项目成果

| 项 | 结果 |
|---|---|
| 全链路 | 飞书私聊 → WebSocket 长连接 → Gateway → DeepSeek → 回复，**打通** |
| 服务化 | systemd 用户级服务 + `enable-linger`，开机自启、SSH 断连不退出 |
| 攻击面 | 入站**仅开放 SSH 22**，面板与 Gateway 均不暴露公网 |
| 访问控制 | 三层防护：云防火墙 → ufw → sshd；fail2ban 实测捕获失败登录 |
| 备份 | cron 每日 04:17 自动备份，保留 30 天；**恢复演练成功（135 个条目）** |
| 补丁 | `apt upgrade` 179 个包，内核 `6.8.0-138 → 147`；重启后**实测开机自启生效** |
| 容量 | 2C2G 上定位到 Gateway 占 1.1G，扩容 swap 至 3.9G 并写入 fstab，重启验证 |
| 日志 | 从 `/tmp`（开机清空）迁至 `/var/log/openclaw`，实测持续写入 |
| 文档 | 部署笔记 + 命令速查 + **14 个真实故障案例** |

## 关键决策

| 决策 | 选择 | 理由 | 代价 |
|---|---|---|---|
| 事件传输 | **WebSocket 长连接** | 服务器主动出站，不需要域名、ICP 备案、HTTPS 证书、新开端口 | 连接断开需重连 |
| 服务托管 | **systemd 用户级 + linger** | 无需 root；开启 linger 后不随登录会话退出 | 多一个容易漏掉的开关 |
| 面板访问 | **SSH 本地端口转发** | Gateway 全程只监听回环地址，公网不可见 | 隧道断开则面板不可用 |
| 防火墙 | **默认拒绝 + 仅放行 22** | 三层独立收敛，任一层失误仍有兜底 | 新增服务需逐层放行 |
| 私聊策略 | **pairing（默认拒绝）** | 陌生人首次对话需人工批准，防止额度被消耗 | 需手动批准新用户 |
| 备份 | **本地归档 + `--verify` + 恢复演练** | 轻量服务器不支持自动快照，必须自建兜底 | 占用磁盘，需自行清理 |

## 故障案例索引

| # | 现象 | 根因 |
|---|---|---|
| 1 | SSH 密钥认证失败 | 云厂商需先「导入公钥」再绑定，不能直接粘贴 |
| 2 | PowerShell 里执行 Linux 命令 | 在错误的解释器里执行 |
| 3 | 云防火墙存在 `ALL` 规则 | 兜底放行等于防火墙失效 |
| 4 | SSH 服务宕机，连接被拒绝 | 配置项拼写错误，sshd 拒绝启动 ⭐ |
| 5 | `Missing privilege separation directory` | `/run` 是 tmpfs，目录由 systemd 创建 |
| 6 | `invalid option` / `missing operand` | 参数与路径之间漏空格 |
| 7 | 命令卡在 `>` 不执行 | 中文引号未闭合，bash 等待续行 ⭐ |
| 8 | `OpenClaw does not know the command "ask"` | 凭记忆猜命令，未查 `--help` |
| 9 | PowerShell 的 `curl` 弹出安全警告 | `curl` 是 `Invoke-WebRequest` 的别名 |
| 10 | 飞书机器人不回复 | 分层排查：连接 → 消息 → 服务 ⭐ |
| 11 | `fallocate: invalid option` 等三条连锁失败 | 小写 `l` 敲成数字 `1` ⭐ |
| 12 | apt 升级卡在 debconf 键盘界面 | 交互式配置在等待输入，不是卡死 |
| 13 | 主配置写了 `PermitRootLogin yes` | drop-in 先加载，`Include` 在文件顶部 |
| 14 | 数据库准入关闭、事务等待 1.6 秒 | 死进程留下的 stale lease ⭐ |

⭐ = 含完整排查过程与预防措施，见[部署笔记](docs/deployment.md#八故障排查记录)。
